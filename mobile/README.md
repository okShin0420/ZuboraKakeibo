# ズボラ家計簿 モバイルアプリ

React Native・Expo・TypeScriptの新しいアプリです。既存の`frontend/`はWeb画面の参照実装として残しています。

端末内SQLiteのスキーマ移行、月度計算、端末内Repository、主要画面、バックアップ・復元、端末内の月初通知予約を用意しています。公表済みの2025〜2027年の祝日データはアプリに同梱し、初回起動時に端末DBへ登録します。通常の記録・閲覧にREST APIは不要です。Web版からの既存データ取り込み、通知の実機検証を含む最終確認は未完了です。

## 起動

Node.jsを用意して、リポジトリのルートから実行します。

```powershell
Set-Location mobile
npm install
npm start
```

開発用のExpoサーバーが表示する案内に従い、実機またはエミュレーターで開きます。依存関係は`mobile/package-lock.json`で固定します。

iOSのネイティブ起動画面は文字や犬のない青一色の `assets/ios-launch-screen.png` を使います。これは `scripts/generate-ios-splash.ps1` で再生成できます。読み込み完了まで表示し、0.5秒より早くは閉じません。その後、約0.28秒で次の画面へフェードします。開発版では設定画面の「開発用」→「iOS起動画面をプレビュー」から同じ動きを確認できます。プレビューは自動で戻り、閉じるボタンはありません。動きを減らす設定ではフェードを省きます。Expo Goの起動画面は配布版と異なるため、最終的な表示はiOSのプレビュー／Releaseビルドで確認してください。

## 端末内DB

`expo-sqlite`の`SQLiteProvider`が起動時に`zubora-kakeibo.db`を開き、`src/database/initializeDatabase.ts`が未適用の移行を順に適用します。現在のスキーマはバージョン5です。V1で基礎テーブルを作り、V2で未設定月度の予算0円に対応し、V3で通知時刻、V4で0円の設定済み状態、V5で説明画面の完了状態を追加します。スキーマの変更時は`src/database/migrations.ts`へ新しい番号の移行を追加し、適用済みのSQLは書き換えません。

移行番号はSQLiteの`PRAGMA user_version`で管理します。各移行のSQLと番号更新は同一トランザクションで行い、失敗時にロールバックします。未管理の既存DBや、このアプリより新しいバージョンのDBは安全のため自動変更せずエラーにします。設定値や支出の初期データは投入しません。

Expo Goで開発中のDBを確認する場合は、Expo CLIの開発メニューから`expo-sqlite`のインスペクターを利用できます。なおWeb版のバックエンドDBから端末へのデータ移行は今回のスキーマ移行とは別工程です。

## 月度計算とRepository

予算と1件の支出は0〜9,999,999円（支出は1円以上）を入力できます。金額キーは7桁で入力を止め、ホーム・設定・入力／編集・カレンダー・グラフでは表示幅に応じて文字を縮小します。複数支出の合計や旧データは7桁を超える場合も表示します。

`src/domain/period.ts`は、開始日1〜31日の月末丸め、土日祝の直前平日への前倒し、次月度の開始日の前日を当月度の終了日とする計算を行います。日付は`YYYY-MM-DD`で、曜日計算はUTCに固定し、端末のタイムゾーンで月度境界がずれないようにします。

`src/repository/LocalRepository.ts`は初期設定、月度の自動繰り越し、支出の登録・編集、現在予算と設定の取得・更新、ホーム・カレンダー・グラフ用の集計を提供します。画面からは`useLocalRepository()`で利用できます。複数行を変更する処理はSQLiteの排他トランザクションで行い、UUIDは`expo-crypto`、日時はアプリ側で生成します。通常利用の処理にREST APIは不要です。

土日祝調整用に、内閣府公表の2025〜2027年の祝日・休日を`src/database/bundledHolidays.ts`からオフライン登録します。2027年以前で対象年の完全な祝日データがない場合は月度生成を停止します。2028年以降の未収録年は暫定的に土日のみ調整し、完全な年データを同梱または`importHolidayYear()`で登録した後に新たに計算する月度では祝日も反映します。既に保存済みの月度境界は自動では変更しません。

## 画面接続

初期予算、ホーム、支出入力・編集、カレンダー、グラフ、設定、今月使える金額の画面は`LocalRepository`へ接続しています。保存した支出・予算・設定は端末内SQLiteへ反映され、ホームや集計を再読込します。画面はWeb版と同条件のスクリーンショットで比較・調整していますが、iOS/Android実機での見た目・操作・アクセシビリティ確認は別途必要です。

月初通知はON/OFFだけを設定できます。ONの場合、Asia/Tokyo基準で今後12回の月度開始日の9:00に端末内通知を予約します。土日祝調整後の開始日を使い、月度ルール・ON/OFF変更、バックアップ復元、アプリ再起動・フォアグラウンド復帰時に予約を照合・更新します。OFFではアプリ管理下の月初通知のみ取り消します。端末側の通知許可がない場合は設定画面に案内を表示します。サーバー通信は不要です。12回より先の予約は、次回アプリ起動・復帰時に補充します。OSの省電力制御などにより配信時刻が前後する可能性があります。

新しい月度の予算が未設定なら、通知が届いたかどうかに関係なく、次にアプリを開いたときに青い金額設定画面を表示します。最初から表示される数字キーパッドで0円以上の金額を入力し、「家計簿をはじめる」で保存するとホームに進みます。0円のままでも開始でき、設定済みとして保存するため次回起動時に同じ画面を繰り返しません。前月の予算は引き継ぎません。

開発中に実機で画面を確認する場合は、設定画面の「開発用」→「新しい月度画面をプレビュー」を選びます。このプレビューは画面表示だけを行い、開始ボタンを押しても現在の予算を変更しません。項目は開発版でのみ表示されます。

## バックアップと復元

設定画面の「全データを削除」は確認後に端末内の予算・支出・メモ・設定・説明完了状態とアプリ内の自動バックアップを削除し、初回説明へ戻します。アプリが予約した月初通知も取り消します。外部に手動保存したバックアップファイルは削除されません。

設定画面の「アプリについて」から[プライバシーポリシー](../docs/PRIVACY_POLICY.md)をオフラインで閲覧できます。本文は`src/legal/privacyPolicy.ts`に同梱し、公開用Markdownとの一致を自動テストで確認します。App Store申請前には公開URLを別途用意し、Release実機で通信・ログと表示内容を照合します。

設定画面の「データ」から、設定・月度ルール・月度予算・支出を1つのJSONファイルとして共有できます。形式識別子は`zubora-kakeibo-backup`、現在の形式バージョンは`2`です。同梱祝日はアプリ起動時に再登録できるため、バックアップには含めません。JSONは暗号化されておらず、予算・支出・メモをテキストで読めます。共有前に注意を表示し、保存先・共有相手を利用者が選びます。

復元ではファイル形式、バージョン、型、日付、金額、ID重複、月度の連続性、参照関係をDB変更前に検証します。検証済みデータはSQLiteの単一トランザクションで置き換え、失敗時は全変更をロールバックします。初期設定前の新しい端末でも、金額設定画面から復元できます。現在データがある場合は、置換前にアプリのドキュメント領域へ`backups/auto-before-restore-*.json`として自動保存し、設定画面の「復元前のデータに戻す」から直前の状態へ戻せます。自動バックアップは新しい5件を保持し、6件目以降は保存を確認した後に古いものから削除します。削除した自動バックアップはアプリ内から復旧できません。手動で外部に保存したJSONは削除しません。自動バックアップは最大20MBなので、保持領域は最大約100MBです。容量不足で自動保存できない場合はDBの置き換えを開始しません。20MBを超えるファイルは読み込みません。バックアップの共有メニューを開いた後は、ファイルアプリなどへの保存先選択を確認してください。

```powershell
npm.cmd test
```

このコマンドは月度計算、SQLite互換アダプター上のRepository、祝日同梱処理、通知日時・予約更新、バックアップ検証・復元・ロールバックを検証します。Expo Go実機でのファイル共有・選択、通知許可・配信、画面確認は別途必要です。

## Web版との画面比較

`frontend/`のViteサーバーを`127.0.0.1:5173`、Expo Webプレビューを`localhost:19006`で起動した上で、別のPowerShellから次を実行します。Expo Webは比較用であり、配布するネイティブアプリの代替検証ではありません。

```powershell
Set-Location frontend
$env:VISUAL_QA = '1'
npm.cmd test -- tests/visual-parity.spec.ts --workers=1
```

比較画像は`frontend/test-results/`に生成されます。小型画面も確認する場合は、実行前に`$env:VISUAL_WIDTH = '320'`と`$env:VISUAL_HEIGHT = '667'`を設定します。テストは固定日時・同じ予算と支出を使用し、SQLiteを持つExpo Web版とAPIモックを使うWeb版の主要画面を撮影します。実機のセーフエリア、フォント、ぼかし、キーボードは端末スクリーンショットで最終確認してください。
