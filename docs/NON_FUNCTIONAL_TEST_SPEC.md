# ズボラ家計簿 モバイル版 非機能テスト仕様書

## 1. 目的・適用範囲

端末内だけで使う Expo／React Native 版が、日常的に安心して使える品質かを、再現可能な条件と合否基準で判断する。対象は `mobile/` の iOS・Android 配布用ビルド。iPad は `mobile/app.json` で対応が有効なため対象に含める。Web モック、Spring Boot、Web 版データの移行は対象外とする。

本書は**実施前の仕様**であり、合格実績を示すものではない。既存の自動テストは一部のデータ整合性・通知予約・バックアップ処理を確認するが、端末固有の操作、OS のファイル共有・通知、性能は実機で判定する。

### 参照する一次情報

- プロダクト方針：`README.md`、`AGENTS.md`
- 画面・操作：`docs/design/DESIGN.md`
- DB・期間：`docs/database/DATABASE_DESIGN.md`、`mobile/src/database/migrations.ts`
- 実装：`mobile/App.tsx`、`mobile/src/backup/`、`mobile/src/notifications/`、`mobile/src/ui/`

### 優先度とリリース判定

- **P0**：データ消失・誤集計・個人データ漏えい・主要操作不能につながる。全件合格をリリース条件とする。
- **P1**：継続利用・アクセシビリティ・体感品質に明確な支障がある。原則全件合格。未達なら影響と回避策を記録してリリース判断する。
- **P2**：限定的な環境の改善項目。未達は期限と担当を記録する。
- 実施不可は「合格」扱いにせず、理由・代替証跡・残るリスクを記録する。数値閾値はこの版の受入基準であり、初回測定値に応じて変更する場合は**測定前に**改訂履歴へ理由を残す。

## 4. 実施順と完了条件

1. 固定データD0〜D4を準備し、ハッシュ・件数・金額合計・月度別合計を控える。実データのコピーは使わない。
2. `mobile/`で `npm.cmd test` と `npx.cmd tsc --noEmit` を実行し、結果を添付する。これは実機テストの代替ではない。
3. Release ビルドで P0 → P1 → P2 の順に実施する。復元・容量不足・強制終了の試験はテスト専用端末／DBで行い、各試験前に元データを別媒体へ保管する。
4. 不合格を修正した場合は該当ケースに加え、起動・保存・復元・新月度分岐を再実施する。端末／OS固有なら同系統端末でも確認する。
5. 全ケースに「合格／不合格／実施不可」、証跡、再現手順、残リスクを記入する。P0全件合格かつP1の未達に明示的な判断が付いた時点でリリース判定を行う。
