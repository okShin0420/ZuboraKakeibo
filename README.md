# ズボラ家計簿-ZUBOLUCK-

> 入力は金額だけ。  
> がんばらなくても続けられる、月のやりくりに特化した超ミニマル家計簿アプリ。

## 概要

「ズボラ家計簿」は、家計簿をつけること自体を目的にせず、**「今月あといくら使えるか」を簡単に把握すること**に特化した家計簿アプリです。

一般的な家計簿アプリにある細かなカテゴリ分けや複雑な入力をなくし、基本的には**金額を入力するだけ**で支出を記録できます。

支出が多い日があっても責めるような表現は使いません。残額が少ないときは、親しみのある口調を保ちながら出費への注意を明確に伝えます。

ホームの犬のコメントは、月度予算に対する残額の割合と残り日数に応じて表示します。予算未設定や残り4日以下など、通常の区分に当てはまらない場合も短い案内を表示します。

将来的にはレシートや購入品の写真から支出を自動記録し、**「家計簿を入力する」という作業そのものをなくすこと**を目指します。

## コンセプト

### 「家計簿をちゃんとつける」をやめる

ズボラ家計簿では、詳細な家計管理よりも「続けられること」を重視します。

- 入力の手間を極限まで減らす
- 月のやりくり額だけを管理する
- カテゴリ分けをしない
- 使いすぎても怒らない
- カレンダーでざっくり振り返る
- 残り予算から今後のペースを教える
- 月末にゆるく振り返る
- 将来的には写真だけで記録を完了する

## MVP

初期リリースでは、以下の機能を実装します。

### 1. 月のやりくり額設定

ユーザーが1か月で自由に使える金額を設定します。

設定項目：

- 今月のやりくり額
- 月初通知 ON / OFF
- 月度の開始日
- 土日祝の自動調整 ON / OFF

月度の開始日は1〜31日から選べます。存在しない日付は月末へ丸めます。土日祝の自動調整が有効な場合は開始日を**直前の平日**へ調整し、次月度の調整済み開始日の前日を前月度の終了日として、月度間に空白を作りません。
開始日または土日祝調整を変更すると、保存済みの過去・現在・将来すべての月度を同じ規則で再計算します。例えば10月7日に開始日を8日へ変更すると、9月度は9月8日〜10月7日、8月度は8月8日〜9月7日です。境界をまたぐ支出は記録日を変えずに該当月度へ移し、残り予算・カレンダー・グラフを再集計します。各月度の予算は月度ラベルに保持し、未作成月度は必要になった時に0円で作成します。新しい開始日が保存日より後なら、その日までは前月度の予算がホームに表示されます。

「今月使える金額」は月度ごとに設定します。未設定の月度は0円で始まり、前月度の金額は自動で引き継ぎません。0円を保存した場合は設定済みとして扱います。グラフでも未設定月度と0円設定月度は0円として表示します。

### 2. 支出記録

支出記録では入力項目を最小限にします。カテゴリ入力は設けません。

#### 必須項目

- 金額

モバイル版では予算と1件の支出の入力上限は9,999,999円です。支出は1円以上、予算は0円から設定できます。金額表示は桁数に合わせて縮小します。

#### 任意項目

- メモ

#### 基本フロー

1. 「入力する」をタップ
2. 金額を入力
3. 保存
4. 残り予算へ即時反映

### 3. ホーム

アプリを開いたときに「今月あといくら使えるのか」がすぐ分かる画面にします。

主な表示：

- 今月の残り予算
- 今日使った金額
- 残り日数
- ゆるいフィードバック
- 「入力する」ボタン

残り予算を画面中央に大きく表示し、情報量を増やしすぎないシンプルなUIを目指します。

ホームには1日あたりの目安を表示しません。画面構成と実装時の優先仕様は [デザイン仕様](docs/design/DESIGN.md) にまとめています。

### 4. カレンダー

カレンダー上に日ごとの支出合計を表示します。日付をタップすると、その日に記録した支出を確認できます。月度表示から2026〜2030年の月を直接選べます。支出は左スワイプで削除ボタンを表示できます。祝日データが未公表の将来年は暫定的に土日のみ調整します。

```text
9月

月   火   水   木   金   土   日
     1    2    3    4    5    6
   ¥800      ¥1,200

7    8    9   10   11   12   13
¥500     ¥3,200
```

## 現在の画面とAPI接続

上記 MVP はプロダクトの目標です。現在の実装は **オンボーディング説明画面・ホーム画面・支出入力ボトムシート・カレンダー画面・グラフ画面・設定画面・初回金額設定画面・新しい月度の金額設定画面**を備えています。月度の自動繰り越しなどは未実装で、MVP全体の完成ではありません。

通信なしで使えるモバイル版への移行を進めています。`mobile/`にExpo・React Native・TypeScriptの主要画面、端末内SQLiteのスキーマ移行、月度計算とRepository、バージョン付きJSONによるバックアップ・復元、端末内の月初通知予約を用意し、画面を端末DBへ接続しました。2025〜2027年の公表済み祝日データは同梱しています。通知を含む実機検証と既存データの取り込みは未完了です。既存の`frontend/`と`backend/`は移行中も仕様と動作の参照に使用します。

- React・TypeScript・Vite、lucide-react を使用。
- DBが空の場合は初期予算入力を表示し、保存後に現在月度を作成します。設定済みなら保存済みの予算・支出を表示します。
- iOSの起動中は文字や犬のない青一色のネイティブ起動画面を表示します。開発版の設定からプレビューできます。
- DB初期化などの起動失敗時もスプラッシュを閉じ、保存データを削除せずに再試行できるエラー画面を表示します。
- 設定画面に祝日調整の対応年（2025〜2027年）と、2028年以降の未収録年は土日のみ調整する旨を表示します。
- バックアップ復元のためにファイルピッカーが作ったアプリ内キャッシュのコピーは、読み取り・検証後、DBを書き換える前に削除します。失敗時も削除を試み、「全データを削除」で残存コピーを処理します。外部に保存した原本は削除しません。
- 犬の吹き出し・呼吸・まばたき・軽い首かしげ。動きを減らす設定に対応。
- 「入力する」で支出入力ボトムシートが開きます。中央の金額をタップすると専用キーパッドが現れ、閉じるボタン、背景タップ、Esc、金額入力後の「保存する」で閉じられます。
- 「保存する」で支出をSQLiteへ保存し、ホームの残額・今日の支出へ反映します。通信エラー時は入力を保持します。
- 上部中央に当月、右に設定を表示します。アカウントアイコンと月の選択操作はありません。
- 下部の「グラフ」で保存済み月度の年別やりくり金額を表示します。棒で月を選択できます。
- 下部の「カレンダー」で日ごとの支出額を確認できます。左右ボタンで月度を切り替え、初期設定した月の前月度（2026年10月に設定した場合は2026年9月度）も表示・記録できます。カレンダーには月度の開始日から終了日までを表示し、翌暦月にまたがる日付もタップして支出を確認・入力できます。リストをタップすると、支出入力ボトムシートで金額とメモを編集できます。
- 端末内データがなく説明も未完了なら、3枚のオンボーディング説明を表示します。「次へ」「戻る」「スキップ」で進み、説明完了を端末内に保存してから初回金額設定へ進みます。説明完了は予算設定とは別に保持します。
- 初回金額設定の青い専用画面「さあ、はじめてみよう」で最初の金額を入力し、「家計簿を始める」を押すと初期設定を保存してホームへ進みます。0円でも開始でき、必要なら同じ画面からバックアップを復元できます。
- 右上の設定アイコンから、ホーム上に重なる設定ボトムシートを開きます。月初通知のON/OFF、月度の開始日、土日祝の自動調整を操作でき、当月度・次月度の範囲を確認できます。通知時刻は9:00固定です。開始日や自動調整を変更すると、過去を含むすべての月度の範囲と各金額へ即時反映し、端末内の月初通知も再予約します。新しい月度の予算が未設定なら、次の起動時に専用画面を表示し、0円を含む金額を設定して「家計簿をはじめる」を押すとホームへ進みます。
- カレンダーは月を切り替えて2030年12月まで支出を登録できます。未作成の月度は表示・記録時に予算0円で作成します。グラフの年選択では2026〜2030年を選べます。
- 「今月使える金額」から専用ボトムシートへ切り替え、画面内の数値キーパッドで金額を入力できます。保存するとSQLiteに永続化し、ホームの残り予算へ反映します。
- 設定画面から設定・月度ルール・月度予算・支出を1つのバージョン付きJSONへバックアップできます。復元前に内容を検証して現在データを自動退避し、SQLiteの単一トランザクションで復元します。
- 設定画面から確認付きで端末内の全利用者データとアプリ内自動バックアップを削除できます。削除後は初回説明へ戻り、アプリが予約した月初通知を取り消します。外部へ保存したJSONは残ります。
- 設定画面の「アプリについて」から、端末内保存・通知・バックアップ・削除について記した[プライバシーポリシー](docs/PRIVACY_POLICY.md)を通信なしで確認できます。
- 芽、カテゴリ、1日あたりの目安、写真入力はありません。

## データベース方針

- 今回の開発ではSpring BootからSQLiteへ保存し、PostgreSQLは使用しません。
- UUIDと日時はアプリケーション側で生成し、SQLiteのDB固有生成関数には依存しません。
- ReactはSpring Boot REST API経由でSQLiteのデータを読み書きします。開発時はViteの`/api`プロキシを使用します。契約は[API設計書](docs/architecture/API_DESIGN.md)を参照してください。
- Spring Boot + SQLiteの起動基盤、Flywayマイグレーション、Entity、DAO、Service、REST Controllerを `backend/` に用意しています。
- 詳細は [データベース設計書](docs/database/DATABASE_DESIGN.md) を参照してください。

### 起動方法

Node.js 22.12 以上と npm を用意してください（[Vite の動作要件](https://vite.dev/guide/)）。

```sh
cd frontend
npm ci
npm run dev
```

プレビュー：<http://127.0.0.1:5173>（このPC内のみ）。停止は実行したターミナルで Ctrl+C。

フロントの起動前に別ターミナルで`backend/`の`mvn spring-boot:run`を実行してください。開発プレビューは<http://127.0.0.1:5173>です。`npm run build`後の`npm run preview`はViteのAPIプロキシを使わないため、別途API接続先を設定した環境で利用してください。

この作業環境では Node.js が未導入だったため、公式配布のポータブル版を `.tools/node-v22.23.2-win-x64` に配置しています。システム設定は変更していません。PowerShell で利用する場合：

```powershell
$env:PATH = "$PWD\.tools\node-v22.23.2-win-x64;" + $env:PATH
Set-Location frontend
npm.cmd run dev
```
